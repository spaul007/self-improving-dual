Belief Layer Anatomy

How the belief document is written, how it predicts, how it is scored, and how its own guidance is optimized — the machine loop that runs between the manager's expand and evaluate events. The meta agent (agentic editor) only reads the result; it never writes a prediction.

LLM call (edit-memory model) deterministic code file on disk (run root or round_NNN/) the belief document itself

1. Where the loop is triggered

The manager (meta_agent/managers/hgm.py) owns every trigger. Nothing in the belief layer runs on its own schedule, and nothing is called by the editor.

2. Tagger — the record every prediction is keyed on LLM

EditMemory.record_node() reads the diff vs the parent plus the editor's strategy.json summary and writes round_N/edit_memory.md: up to max_subedits sub-edits, each tagged with a strategy id and an area id from the run-level registry (new ids are defined on first use; max_strategies caps growth, and a tag forced by the cap is marked fit: forced and never scored). The record also carries the performance line (child vs parent on shared cases, unpaired Δ ± SE) and, later, the judge's verdict lines. edit_code.md stores the diff and changed definitions for the editor to read.

3. register() — the prediction is frozen before the outcome deterministic

  1. Load the node's record tags (drop fit: forced ones) and parse the current edit_memory_beliefs.md.
  2. For each kind in ("strategy", "implementation"), match_belief() picks the most specific belief whose scope matches: strategy + area beats strategy only; ties resolved by sub-edit order.
  3. Write round_N/belief_prediction.json: per kind {slug, p, scope, matched_edit, section} (or null when no belief covers it), plus belief_version, instruction_version, and coverable — true only if an earlier node already used one of this node's strategies. A first-of-its-strategy node is not charged for silence.

This is why the meta agent no longer predicts: the belief document is the predictor, and the prediction is made by construction before anything about the node's outcome is known.

4. The contract — what a belief document must look like deterministic

Grammar (belief_contract.py)

## Summary            (optional, first, ≤ 1200 chars)

### belief:<slug> — <title>
- kind: strategy | implementation
- scope: strategy=<registry id> [area=<registry id>]
- predict: p=<0.05..0.95>
- evidence: … [node N: improved] [node N: regressed; Δ+0.03/12] …
- next: <one concrete move for the editor>
- track: (code-generated, never written by the LLM)

Validation

Hard (reject → one retry → keep old doc)Soft (accepted, counted)
prose above the first belief; unknown section or field; duplicate slug/field; missing required key; bad kind; scope id not in the registry; p outside [0.05, 0.95]; duplicate (kind, scope); no beliefs; document over doc_char_cap citation names a node with no record; cites a verdict or Δ the record doesn't have (misquote) — reported in the track line and the calibration report until corrected

Citations are verified against the deterministic records: [node N: improved] must match the judge's effect verdict; a quoted Δ must be within 0.005 of the record's paired delta.

Loss per scored prediction is (p − y)²; 0.25 is the uninformative baseline. Each Scored row keeps node, kind, slug, p, y, brier, the belief and guidance versions in force at registration, the judge's effect/evidence/reason, and the Δ context. label_source: delta swaps the labels for "Δ ≥ threshold over ≥ min_shared shared cases" (ablation only).

Track lines and the calibration report

After each scoring batch the code regenerates one - track: line per belief (n · Brier · outcomes) and injects it into the document, so the editor always sees current calibration without an LLM call. The report — per belief, worst misses, uncovered measured nodes, not-scored reasons, open predictions, judge-vs-score diagnostic, verdict changes, citation checks — is built once and shared by the rewrite prompt and the optimizer prompt.

6. Optimizer — the guidance text learns from misses LLM

  1. Trigger: scored_since_step ≥ optimize_every (8 in the 1000-eval configs). Guidance starts at SEED_INSTRUCTION (v000).
  2. Rollback first: if the current guidance version has ≥ optimize_min_scored samples and an earlier version's mean Brier is lower by more than optimize_rollback_margin (0.02), restore that text (event revert).
  3. Step: one call with OPTIMIZER_SYSTEM: the window of scored rows since the last step (each with the belief text that made the prediction, the judge's verdict and reason, targeted checks, well-measured score) plus the calibration report → tool submit_instruction_update(critique, instruction), capped at instruction_char_cap (2500; one retry when over).
  4. Persist: belief_instruction.md ← new text; archive vNNN.md, step_NNN_prompt.txt, step_NNN_response.json; state instruction.version bumped and every later prediction stamped with it — that is what makes per-version Brier (and rollback) possible.

7. Rewrite — the document is replaced wholesale LLM

update() reaches the rewrite only if the evidence signature changed (per-node case and analysis signatures, the registry bytes, the prediction joins, salted with BELIEF_FORMAT). The system prompt is fixed contract text — CONTRACT_SYSTEM with SCORING_JUDGE, the grammar, the example and the rules — plus the learned guidance vN. The user prompt carries, in order: run context (seed, best so far, node count), the registry ids allowed in scope lines, the current document with its track lines, the calibration report, the judge ledger (per-strategy verdict tallies) and the deterministic per-strategy ledger, and the full records of the nodes whose evidence changed (newest first, within evidence_char_budget, at most max_delta_records). The old document is archived as beliefs_NNNN.md; every attempted prompt is dumped under edit_memory_beliefs_prompts/.

8. The judge the beliefs are scored against LLM

edit_usage.py analysis v7 runs per node once it has analysis_min_own_evals (16) own cases. Inputs: the implementation view of the diff (added lines grouped by definition, within analysis_code_char_budget), the fire counts of every trace.log point the edit added, per-check pass/fail on the node's own cases, and up to 32 per-case rows. Output (tool call, all fields required): implementation_sound + reason; per sub-edit sound, targeted_checks, effect ∈ {improved, no_effect, regressed, unclear}, evidence ∈ {strong, moderate, weak}, reason; and regressions. These lines are appended to the record and are the only labels scoring uses.

9. What the meta agent sees, and what it cannot touch

In a run with edit memory the agentic editor's instruction lists the run-level files and tells it (step 2) to consult edit_memory_beliefs.md as accumulated understanding, follow its node citations into edit_memory.md / edit_code.md / task_agent/, and diversify. It reads through the bwrap sandbox (live bind of the run root), so an update landing mid-session is visible. It writes only its code and a summary; the only editor input to this layer is the strategy.json text the tagger reads. A run without edit memory has none of these files and its prompt never mentions them.

12. Read on the live run (1000-eval editmem arm, 20% in)

25 updates, 12 scored predictions with mean Brier 0.19 (uninformative = 0.25), 5 skipped as first-of-strategy, guidance at v1 after one optimizer step. The first revision told the writer to predict the judge's verdict rather than the score Δ and to cover every edit type with a committed probability instead of p = 0.5. Beliefs currently rate prompt-only edits sound at p ≈ 0.85 (3/3 correct) and post-plan validation code at p ≈ 0.40 — which is why that arm's edits stayed small and instrumented.
